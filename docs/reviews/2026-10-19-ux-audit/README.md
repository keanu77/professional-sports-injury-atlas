# 運動傷害影片圖鑑：網站優化審查

審查日期：2026-10-19。正式站：https://injury.sportsmedicine.tw/ 。原碼基準：`cc0b2fe`；發布差異另見[當日同步查核](../2026-10-19-live-sync/verification.json)。本輪交付審查與建議，沒有修改產品程式、提交或部署。

最值得投入的是讓「找影片 → 看影片 → 讀懂事件 → 繼續探索」成為一致的流程。沿用現有 A 主視覺、藍色品牌、繁體中文無襯線字體與前方社群入口，調整資訊層次、卡片與詳頁，比再加入裝飾更有明確用途。

## 視覺與版面方向

**首頁。** 品牌介紹保留，但讓查詢工具更突出。標題、搜尋框、結果數構成主要層級；統計數字、次要分類與說明文字退到次要層級。保留藍色作操作色，橘色集中於播放提示；減少每個區塊都以邊框、底色、圓角同時強調。這是要製作原型比較的方向，未以使用者研究證明成效。

**卡片。** 統一呈現「縮圖 → 姓名 → 事件 → 運動／部位／年份 → 影片類型 → 觀看入口」。事件標題保持足夠可讀的行數，次要資訊不要與姓名搶同等字重。類型和來源仍有不同用途，不能為了減少標籤而合併語意。深色模式的觀察卡播放三角形對橘底約 1.97:1，可沿用核心卡既有的深色圖示 token 改善辨識；因為圖示為冗餘且 aria-hidden，不單獨定為 WCAG 違規。

**詳頁。** 一般觀察影片目前已有桌面雙欄；Aaron Judge 這類含較完整事件解析的變體才是單欄、最大寬度 52rem。因此重點是統一閱讀導航與摘要，長文變體另試窄側欄，不能把單一頁的觀察推廣為全站都缺雙欄。建議以下閱讀節奏：

| 桌面 | 手機 |
|---|---|
| 返回清單、事件標題與簡短 metadata | 返回清單、精簡標題與 metadata |
| 主要影片欄，旁邊窄欄放事件摘要／頁內導航 | 影片，再接三個閱讀重點 |
| 傷勢與後續、一般人參考、來源，保持舒適閱讀寬度 | 按相同順序閱讀，頁內連結避免擋住正文 |
| 明確推薦理由與相關分類 | 相關影片、同部位／同運動續看 |

三個閱讀重點可用「發生什麼／目前知道什麼／一般人如何理解」，每點回溯現有來源。警訊、診斷不確定性與適用範圍仍須可見；不把重要內容藏進預設折疊區。既有字級、主題切換與來源資訊保留，不必增加新的中文字體下載。

## 動態呈現

動態應解釋操作狀態。現有網站已有 reduced-motion、結果狀態與延後載入播放器，適合在這個基礎上補齊：

- 篩選選中、結果數改變：短暫色彩或透明度過渡，初稿可試 120–180ms；這是設計起點，不是規範值。
- 播放器：固定尺寸的載入區與「正在載入」文字，成功後移除，失敗保留重試與原始影片連結。
- 載入更多：保持舊卡片位置，新內容出現後能看見焦點。是否有實際焦點超出視窗的問題尚待補測。
- 長文：先做好頁內導航與目前章節提示；只有閱讀測試顯示有幫助時再加入進度指示。

不要讓每次輸入都觸發整批卡片飛入，也不建議加入首頁自動播放、視差背景、持續浮動效果或額外動畫框架。減少動態模式改為立即切換，資訊不能依賴動畫才看得懂。

## 效能與擴充性

首頁當次 HTTP 實測為 **571,598 bytes HTML，gzip 72,425 bytes，5,028 個元素、200 張完整卡片**。目前「每批 24 支」只控制顯示，初次仍建立全部卡片。這是確定的結構與體積事實，尚不能據此判定使用者感到慢。

先量測行動裝置冷載入、搜尋輸入和連續瀏覽，再依結果處理：

1. 影片庫持續增加時，評估前 24 張 SSR＋精簡搜尋索引＋需要時建立後續卡片。無 JS 仍要能透過靜態分頁到達全部內容。
2. 搜尋只更新有差異的卡片，避免每次輸入重新 append 所有可見卡片。
3. 冷載入另有很小的同步偏好腳本、互動入口到共用 chunk 的依賴；先看瀏覽器 waterfall，再決定是否 preload 或以 CSP hash 內嵌固定偏好程式。
4. 主視覺與首卡都設 high priority。桌面首卡在初始可視區外，可評估取消該列表縮圖的高優先權；詳頁主要影片縮圖另行判斷。
5. 全量 inline CSS 與熱門 API 整點結果快取屬後續量測項。現在 JavaScript 很小：搜尋 gzip 約 3.7 KB、播放器約 2.4 KB，沒有換框架的證據。

現場指標目標採 LCP ≤2.5 秒、INP ≤200ms、CLS ≤0.1，依行動與桌面分開看第 75 百分位。本輪沒有取得這些實測結果，也沒有 PageSpeed 分數。[Web Vitals 官方說明](https://web.dev/articles/vitals)

## 內容發現、分享與維護

- 「最近收錄」若要新增，應有真正的 addedAt，不能把事件年份或內容整理日當作新增時間。
- 三個舊傷種總覽仍公開生成，只計核心案例；ACL 為 0，不代表影片庫沒有膝部影片。應說清楚收錄範圍並連接相關影片庫。傷種與部位不是同義詞，不應直接批次轉址。
- 字級 A−／A＋到上下限時補上狀態回饋；維持現有觸控尺寸，不在手機頁首堆太多文字。
- 清理已退出渲染流程的 InjuryCard、無 consumer 的 scoped CSS 與過時測試。這是維護改善，不宣稱能帶來可量測的速度提升。
- 發布前重新取得影片播放證據；後續可規劃失效連結與來源更新檢查。這輪沒有逐支播放 200 支影片，也沒有驗證播放失效率。

## 證據與限制

第一輪候選分為[結構](pass1-structure.json)、[無障礙](pass1-accessibility.json)、[效能](pass1-performance.json)、[視覺](pass1-visual.json)、[安全與發布](pass1-security.json)。[第二輪獨立複核](pass2-verified.json)實際重讀原碼、consumer 與相關測試，並重新下載頁面、計算配色及執行分類／推薦函式。候選與修復項不等量，設計提案也不等於網站缺陷。

29 筆候選經複核分為：5 筆確定缺陷、12 筆設計提案、8 筆量測／原碼事實與優化假說、1 筆發布落差、3 筆待重現；另排除 5 種過度推論。待重現項未列入確定缺陷。第一輪原始定位或措辭若與第二輪不同，以第二輪修正為準。

原有能力值得保留：響應式 AVIF/WebP、縮圖尺寸預留、點擊後才載入第三方播放器、URL 搜尋狀態、中文 IME 處理、來源與適用範圍、reduced-motion、主題和字級設定。這次以補齊流程和細節為主。
